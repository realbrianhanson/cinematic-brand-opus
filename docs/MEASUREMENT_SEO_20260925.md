# Giveaway measurement and crawlable content navigation

## Delivered

- Added `/first-ai-build` to browser, collector, and database public-path allowlists. Four fixed planner actions carry a fixed project ID and, for training clicks, a published offer ID. Unknown fields are removed before transmission. Existing consent, privacy signals, preview/admin/QA exclusions, private reporting, retention, and revocation apply.
- The Conversion dashboard reports consenting sessions that visited, created a plan, copied its prompt, started a download, and clicked a training listing. These are overlapping actions, not claims of a completed sequential funnel, successful file saves, or sales. Older backends show measurement unavailable instead of false zeroes.
- Blog archive pages now have persistent URLs such as `/blog?page=2` and `/blog?category=tutorials&page=2`. Their own article cards, canonical, title, and previous/next links are server-rendered. Filters remain in pagination URLs; irrelevant query parameters are excluded from canonical URLs. Page input is bounded. Empty later pages return 404; database failures remain retryable. A one-card lookahead avoids linking an exact 12-card final page to an empty page. The legacy crawler renderer observes the same pagination input and keeps self-canonical URLs.
- Guides server-render links to published resources connected by the actual stored niche ID and an active content format. This improves the existing explicit relationship without inventing a topic match. Resource reads are bounded at 100 and use only public columns. A failed optional resource lookup does not hide the guide; the client retries with a visible recovery control.
- The legacy renderer recognizes the planner as an app route and avoids recording it as missing.

## Deployment

Apply `20260925110000_first_ai_build_measurement.sql`, deploy `conversion-events` and `render-page`, and release the frontend. ## Verification

Behavioral coverage includes no transmission before consent, event payload omission of all business and prompt text, rejection of invalid project/path/action combinations, successful-only clipboard reporting, download start reporting, training offer identification, archive normalization/server loading/404/canonical links, server-rendered anchors, and exact stored guide relationships. The isolated PostgreSQL conversion suite applies the new migration and checks event idempotency, published-offer validation, bounded data, report session counts, revocation, private grants, retention, and existing purchase accounting.

The root release pass runs the complete test/build/check suite and independent reviews. No live measurement events or content mutations were generated by these checks.
