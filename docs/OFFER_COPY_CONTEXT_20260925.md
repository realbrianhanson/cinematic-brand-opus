# Funnel copy context

The admin copy assistant now considers the current page in section order, its call to action and supporting microcopy, FAQs, proof references, and manually entered terms. It receives the current unsaved working page, so a previous saved version cannot silently override recent edits.

## Context and authority

- All 30 supported section positions and types are represented. Body/caption excerpts share a 24,000-character budget. Ordinary bodies use up to 1,200 characters; exact guarantee sections have first priority and use up to 6,000 each. Every omission is marked. Requests have a 384 KiB byte limit before JSON parsing.
- The selected copy section still has its full allowed body. Full headline, subheadline, eyebrow, CTA label and microcopy are included. Image/video URLs, private proof notes, payment links and assets are excluded.
- Complete owner-entered guarantee sections are isolated as commercial context, never as independently verified promises. Incomplete terms are marked unknown. The model cannot apply changes to guarantees, proof sections, prices, checkout settings or publication.
- Only proof records loaded server-side with `approved = true` may substantiate results. Existing page wording, brief evidence and parent descriptions remain source data, not instructions or independent evidence. Pricing authority remains the structured pricing context; provider-controlled or unset prices remain unknown.

## Previous-product context

The browser supplies only this saved offer's ID. For an upsell page the authenticated server reads published native offers whose `next_offer_id` points to it. It verifies row shape and connection before using bounded title, description and included-item excerpts. It never accepts client-provided previous-product facts.

One predecessor permits a specific optional transition. Multiple predecessors require a general transition suitable for every entry path. A free predecessor is described as claimed, not purchased. No predecessor, an unsaved offer or incomplete context cannot justify assumptions about a past purchase. A failed database query fails the request rather than pretending no predecessor exists. Four rows detect more than three predecessors; three descriptions are supplied and additional predecessors are explicitly marked.

The response adds deterministic warnings for missing/ambiguous predecessor context and truncated page excerpts even if the model omits them. All suggestions remain review-only until the owner explicitly applies one; changed drafts still invalidate older suggestions.

## Validation and limits

Coverage includes ordered whole-page/CTA transport, bounded excerpts, exact/incomplete terms, approved-proof isolation, data/rule separation, relationship validation, ambiguous/missing/free predecessors, parent inventory truncation, reliable warnings and existing apply/cancel/stale-draft behavior. No paid generation or production write is needed for these tests.

This improves available grounding and editing instructions; it cannot mechanically prove every sentence generated by a model. Owners must still review factual claims. There is no inference of actual customer purchase history, no new payment capability, and no automatic publishing. Real model output quality still needs evaluation with representative saved offers in the authorized test environment.
