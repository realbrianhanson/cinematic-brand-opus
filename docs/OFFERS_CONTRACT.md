# Offers implementation contract

Owner request: free and paid digital lead magnets, shareable pages, explicit upsells/OTOs in admin, Stripe-ready with no keys required now, plus standalone external/affiliate products in the Shop. No native subscriptions, no automatic card charges, no newsletter subscription or actual QA email/payment. Fixed prices support USD/CAD/EUR/GBP/AUD, integer minor units. Native paid flow is hosted Stripe Checkout with server-side keys only; external products link to the provider without creating local leads, orders, or access tokens.

## Database

- `offers`: id uuid PK, slug text unique, title text, summary text, body text (plain paragraphs), cover_url nullable text, status `draft|published|archived`, kind `free|paid`, amount_minor integer, currency text default usd, asset_path nullable text (PRIVATE), asset_name nullable text, thank_you_message text, next_offer_id nullable FK offers, next_offer_window_minutes int default0 (0=no timer, otherwise 30..10080), funnel_only bool default false (must have valid parent to claim), created_at/updated_at timestamptz. Shop fields: show_in_shop bool default false, shop_category `training|resource|tool|course`, shop_featured bool default false. Checkout fields: checkout_mode `native|external` default native, price_display_mode `fixed|provider` default fixed, external_url nullable text, external_button_text text default empty, is_affiliate bool default false, affiliate_disclosure nullable text. Published offers require title/summary; native offers also require asset_path/name. Admin RLS all; anonymous select is limited to public presentation fields on published rows, including the six checkout fields and the Shop fields. No anonymous asset paths, order data, or next-offer configuration. Prevent graph cycles on writes. No destructive deletes with orders; admin archives.
- `offer_orders`: id uuid PK, offer_id FK restrict, parent_order_id nullable FK restrict UNIQUE (one next purchase per parent), token_hash text unique, email/name, status `pending|fulfilled|failed|expired|refunded`, title_snapshot, asset_path_snapshot, asset_name_snapshot, amount_minor, currency, next_offer_id nullable, next_offer_window_minutes, next_offer_deadline nullable, declined_at nullable, stripe_session_id unique nullable, stripe_payment_intent_id nullable, stripe_checkout_url nullable, checkout_expires_at timestamptz, created_at/fulfilled_at. Admin SELECT only, service writes. No public access. Tokens do not expire automatically; refunds revoke access; signed file URLs last300s.
- `offer_stripe_events`: event_id text PK, event_type text, created_at. Service only.
- private bucket `offer-files`; admin insert/select ONLY. Version UUID paths, do not delete files used by existing orders. No anonymous storage read.

Checkout constraints:

- Native offers use fixed pricing and retain their existing file, free/paid, checkout, and fulfillment rules. Existing order snapshots remain valid when an offer is later edited.
- External offers are standalone: funnel_only=false, next_offer_id=null, next_offer_window_minutes=0. They cannot be follow-up targets. The database also blocks converting a target referenced by another offer or by an existing order's next_offer_id into an external offer.
- Published external offers require a valid absolute HTTPS external_url, but no private file or Stripe configuration. Destinations reject credentials, whitespace/control characters, backslashes, and values over 2048 characters. Preserve the destination's query parameters and fragment. Never fetch an external destination server-side.
- External fixed/free uses amount_minor=0. External fixed/paid requires a valid paid amount (minimum50 minor units). External provider pricing requires kind=paid and amount_minor=0; its public label is **View current pricing**, never Free or a zero monetary price. Provider pricing is unavailable for native offers.
- When is_affiliate=true, display custom disclosure as plain text or the fallback **Affiliate link: I may earn a commission if you purchase through this link.** beside and before the outbound button. Affiliate anchors use rel="sponsored noopener noreferrer"; other outbound anchors use rel="noopener noreferrer". Both open in a new tab and identify the provider hostname.

Service-only RPCs:

1. `offer_reserve_order(_offer_id uuid,_token_hash text,_email text,_name text,_parent_hash text default null)` returns jsonb full order. Reject new reservations for external offers. Atomically validate published native offer and valid asset, lock parent if supplied; exact parent nextoffer, fulfilled, notdeclined, deadline, sameemail; enforce funnel_only; max chain10/no repeated ancestoroffer. Idempotent same token with same request context returns same order; mismatch rejects. Pending paid, fulfilled free. Snapshot all delivery/amount/nextoffer fields. Free fulfilled_at now + optional next deadline; paid deadline starts upon fulfillment. Pending checkout_expires_at now+60min. Parent unique prevents duplicate child; a retry must reuse token.
2. `offer_record_checkout(_order_id uuid,_session_id text,_checkout_url text,_payment_intent_id text default null)` safely associate session to pending order, idempotent same session, reject mismatch. Webhook may race this call; permit same association on already fulfilled order.
3. `offer_apply_stripe_event(_event_id text,_event_type text,_session_id text,_order_id uuid,_payment_intent_id text,_amount_minor integer,_currency text)` atomic receipt + row lock. For checkout.session.completed or async_payment_succeeded call ONLY after verified paid event; verify order amount/currency/session, fulfill preserving refunded terminal status; set deadline once. async_payment_failed/session.expired update only pending. charge.refunded uses payment intent ID lookup and revokes access (conservative on any refund). Duplicate events are no-ops. Reject paid amount/session mismatches without swallowing event receipt. Return jsonb status.
4. `offer_decline_next(_token_hash text)` sets declined_at on fulfilled parent unless a child already exists; original download remains available. Return void/json either backend normalizes.

## Edge API

`offers-api`: POST JSON with action. OPTIONS CORS, bounded JSON, durable hashed-IP/email/token throttling via existing newsletter_rate_limit_hit. All responses JSON/no-store.

- `{action:'get', slug}` -> `{offer:PublicOffer|null,payments_ready:boolean}` published only; include funnel_only page details but no claim without parent. Admin JWT can preview draft with `{action:'preview',offer_id}`.
- `{action:'health'}` actual admin JWT required -> `{secret_configured,webhook_configured,payments_ready,mode:'test'|'live'|'unconfigured',webhook_url}`. Configured means both secrets present; do not claim live transaction verified.
- `{action:'claim',offer_id,email,name,token,parent_token?}` free OR paid; token client256bit lowerhex64; validate. Paid without keys returns503 with code `payments_unavailable` BEFORE reserve. Atomic RPC -> free `{status:'fulfilled',access_url}` or paid `{status:'pending',checkout_url,access_url}`. Stable orderid Stripe idempotency, immutable price_data/title snapshot. No customer-supplied amount/redirect. Canonical origin from site_settings.site_url, validated HTTPS. success `/offer-access#token=...`; cancel same access URL. Both secrets required. Pending retry same token returns same checkout, never create second session after expiry/uncertainty; client can checkstatus. No one-click/offsession charges.
- `{action:'status',token}` -> `{order:{id,title,status,kind,amount_minor,currency,asset_name,fulfilled_at},next_offer:PublicOffer|null,next_offer_deadline:string|null,checkout_url:string|null,access_url}`. Verify tokenhash; no rawemail/privatepath returned. Next available only fulfilled, notdeclined, notexpired and no child; paid next hidden/disabled via payments_ready response. Return `payments_ready` too. Pending may return storedcheckout forresume before expiry. It may safely retrieve Stripe session server-side to reconcile through same RPC (optional), never trust browser success.
- `{action:'download',token}` -> `{url,filename}` short signed URL iffulfilled snapshot asset; no publicfilepaths elsewhere.
- `{action:'decline',token}` -> `{ok:true}` atomic disable nextoffer; doesn't affect original asset.

`get` and `preview` include all six public checkout fields. `payments_ready` describes native Stripe configuration only and does not gate external links. New external claims are rejected before readiness/reservation/payment work; download/status continue to honor existing native order snapshots. No external redirect, click, or payment is treated as proof of a local purchase.

`offer-stripe-webhook`: POST raw body bounded; official Stripe SDK async webhook verification with timestamp tolerance. checkout.session.completed and async_payment_succeeded require mode=payment, payment_status=paid, metadata.offer_order_id valid + amount/currency. asyncfailure/expired updatepending. charge.refunded revokes via paymentintent. Event receipt/fulfillment atomic. No keys ->503. No content/provider calls in QA.

## Frontend

Shared TS contract types in src/lib/offers.ts root-owned. Use generated Supabase table types for admin CRUD; edge invokes through `invokeOfferApi<T>` wrapper (root will expose). `PublicOffer` equals public columns above. `OfferHealth`, `OfferAccess` match responses. Tokens in fragment and POST body, remove hash immediately, persist browser session before starting checkout. No token in query, external referrer, analytics. Access page noindex+no-referrer, save/copy access link.

Admin `/admin/offers` index with list + setup readiness; `/admin/offers/new` and `/admin/offers/$id/edit`; root will add nav. Admin create/edit/upload PDF/ZIP/EPUB/text, cover HTTPS URL, plain copy, free/paid price, publication status, follow-up offer dropdown + timer + funnel-only option, duplicate optional, sharelink/copy, preview. Orders/leads tab in list with counts/filter and honest pending/refunded states. No actual demo rows automatically created. Files upload UUID prefix, size<=25MB, allowed PDF/ZIP/EPUB/text MIME.

Public `/offers/$slug` SSR explicitpublishedselect metadata404, styled with sitebrand. Native pages show the client checkout form name/email, readiness and explicitamount. External pages render a separate component with the provider link and pricing/disclosure; they never initialize native readiness requests, forms, token storage, or claim calls. Preview via admin session edge preview noindex, draft neverpublic; both native forms and external outbound buttons are disabled in preview. `/offer-access` polls pending bounded and supports retry status, keeps download accessible during upsell, shows optional native nextcard accept/decline. Each accept creates NEW token persisted for child, parenttoken authorizes, inherited email should be fetched server-side from parent so client email can omit for child. IMPORTANT backend should accept omitted childemail and derive it from parent beforeRPC; UI won't receive parentemail.

`/shop` includes only published, show_in_shop=true, funnel_only=false offers. Native and external cards share category/search/free-paid filters; provider-priced offers remain paid. All cards link to the local `/offers/$slug` detail page, where the external disclosure and provider destination are visible before leaving. The Shop and offer SSR projections explicitly include the six checkout fields and exclude private files/orders. Sitemaps retain local detail URLs with the same published/listed/non-funnel filter.
