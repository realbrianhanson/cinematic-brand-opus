### Independent review follow-up

- Widget writes and list refreshes now have 15-second deadlines and pass AbortSignals to Supabase. Read retries are explicit so retry backoff cannot extend a held reorder lock. Both mutation and refresh failure paths release their controls; a single stalled save returns to Retry with its draft intact.
- Before each widget write, the client reads its current `updated_at` and makes the update conditional on that version. This uses the existing database column/trigger and needs no migration. Aborting a request cannot undo accepted server work: the version predicate ensures a delayed old write cannot replace a newer committed value. Tests delay an old request until after the new one succeeds and verify both stored and displayed values stay current.
- Content-format and guide controls are frozen while saving, including the guide's rich-text editor. This prevents newer typing from leaving a successfully inserted record on its create route or keeping a newly published guide on stale draft state. Tests cover a new format insert, a new guide insert, and publishing a guide; all navigate with a clean submitted baseline.
- News image uploads now release their lock after 30 seconds. A late completion has no remaining continuation that can patch the current image; a new attempt uses a separate object path. The installed storage SDK has no upload AbortSignal option, so a timed-out request may leave an unused uploaded file on the server. The editor retains text and remains usable. Tests cover timeout, a successful retry, and the ignored late original completion.
- Guide sharing-image uploads now use the same bounded wait and guaranteed cleanup. Rejected or stalled uploads re-enable Save and uploading controls, selected files can be retried, and a late original completion cannot replace a retried image or another guide's image. Two further regressions cover rejection and timeout/retry/late completion.

## Remaining operational limits

- The new leave guard warns before losing unsaved data; it is not a persistent working-copy system. PostEditor retains the existing persistent recovery implementation. A browser crash/device failure is outside the new guard's guarantee.
- Widget reorder still uses two writes. A partial failure is reported and actual saved order is reloaded; atomic reorder would require a backend transaction/RPC. Widget cards remain mounted across zone changes so an in-flight or failed draft and its Retry control survive switching tabs.
- Public/private settings are separate writes. Failures cannot be rolled back atomically by the frontend; successful completion is reported only after both calls succeed.
- No authenticated live-provider checks were performed here. Missing managed backend migrations/functions, configured credentials, provider delivery and service quotas still need the coordinator's release verification. Frontend tests do not install backend dependencies.
- Offer/funnel features and public-site/browser verification belong to separate coordinated audit scopes. This report does not claim their coverage.
